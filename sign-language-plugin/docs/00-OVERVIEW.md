# 00 — نظرة عامة تنفيذية

## 1. المشكلة التي تُحلّ

الأشخاص الصمّ الذين يستخدمون لغة الإشارة كلغة أولى **ليسوا بالضرورة قارئين بطلاقة للغة المكتوبة**. لغة الإشارة لها نحو (grammar) مستقل تمامًا عن اللغة المنطوقة المحيطة بها — ترتيب الكلمات مختلف، لا توجد أدوات تعريف، والزمن يُعبّر عنه مكانيًا. لذلك ترجمة النص إلى لغة إشارة **ليست ترجمة حرفية كلمة بكلمة**، بل ترجمة بين لغتين مختلفتين بنيويًا.

الحل الذي اتبعته Hand Talk: تحويل نص الصفحة إلى تسلسل من **الوحدات الإشارية (glosses)**، ثم تشغيل أنيميشن مسجّل مسبقًا لكل وحدة على أفاتار ثلاثي الأبعاد داخل المتصفح.

---

## 2. المفاهيم الأساسية

| المصطلح | التعريف | مثال |
|---|---|---|
| **Gloss** | الوحدة المعجمية في لغة الإشارة — تُكتب عادةً بأحرف كبيرة | `HOUSE`, `GO`, `YESTERDAY` |
| **Fingerspelling** (التهجئة الإصبعية) | تهجئة كلمة حرفًا بحرف عندما لا توجد إشارة لها | `P-L-U-G-I-N` |
| **Non-manual markers** | تعابير الوجه والحاجبين — جزء **نحوي** لا تجميلي | رفع الحاجبين = سؤال نعم/لا |
| **Rig / Skeleton** | الهيكل العظمي للأفاتار | 119 عظمة في Hand Talk |
| **Morph target / Blendshape** | تشويه هندسي للوجه للتعبيرات | 60 هدفًا في Hand Talk |
| **Retargeting** | نقل حركة مسجّلة من هيكل إلى هيكل آخر | من ممثل بشري إلى الأفاتار |

> **تحذير هندسي مهم:** إهمال تعابير الوجه يُنتج ترجمة **غير مفهومة** أو مضلّلة. هي ليست ميزة اختيارية.

## 3. النموذج الذهني للنظام

```
نص المستخدم
    │
    ▼
[طبقة التقاط النص]  ←─ في المتصفح: يلتقط التحديد أو النقر
    │
    ▼
[محرك الترجمة]      ←─ على السيرفر: NLP يحوّل الجملة إلى glosses
    │                   "Hand Talk Plugin" → [SIGN_HANDTALK] + [P,L,U,G,I,N]
    ▼
[قاموس الأنيميشن]   ←─ على السيرفر: لكل gloss مسارات حركة مضغوطة
    │
    ▼  (استجابة ~1 KB نصية)
[فك الترميز]        ←─ في المتصفح: نص → THREE.AnimationClip
    │
    ▼
[مشغّل three.js]    ←─ طابور تشغيل + انتقالات ناعمة (crossfade)
    │
    ▼
أفاتار متحرّك على الشاشة
```

## 4. القرار المعماري الأهم

Hand Talk **لم تختر** توليد الحركة بالذكاء الاصطناعي في الزمن الحقيقي. اختارت **استرجاع من قاموس مُعدّ بشريًا** (retrieval, not generation). لماذا؟

| المعيار | استرجاع من قاموس (المُتّبع) | توليد عصبي في الزمن الحقيقي |
|---|---|---|
| دقة لغوية | عالية — مراجَعة بشريًا من مترجمين صمّ | متغيّرة، عرضة للهلوسة |
| زمن الاستجابة | 200–400 ms | ثوانٍ + GPU |
| تكلفة التشغيل | استعلام قاعدة بيانات فقط | GPU لكل طلب |
| حجم الاستجابة | ~1 KB | ميغابايتات |
| التوسّع لمفردات جديدة | يتطلب تسجيل يدوي (بطيء) | تلقائي نظريًا |
| القبول لدى مجتمع الصمّ | مرتفع | منخفض حاليًا |

**التوصية:** ابدأ بنفس النهج. النموذج العصبي يمكن إضافته لاحقًا كطبقة تحسين للانتقالات بين الإشارات (co-articulation)، لا كمولّد أساسي.

## 5. ما الذي رُصد فعليًا في ملفات HAR

| القياس | القيمة المرصودة |
|---|---|
| حجم `handtalk.min.js` (المُحمّل في كل صفحة) | **546 KB** |
| حجم `core.min.js` (محرك 3D، يُحمّل عند التفعيل فقط) | **809 KB** |
| حجم موديل الأفاتار `HUGO.gltf` | **3.57 MB** |
| ملفات الأنيميشن الجاهزة (رسائل النظام) | 7 ملفات، ~97 KB |
| زمن مصادقة الجلسة `/api/v2/sign/auth` | **319 ms** |
| زمن ترجمة جملة قصيرة ("HAND TALK") | **418 ms** / استجابة 1.0 KB |
| زمن ترجمة فقرة (487 حرفًا) | **1877 ms** / استجابة 121 KB |
| حدّ المعدّل (rate limit) | **300 طلب** لكل نافذة زمنية |
| معدّل الإطارات في الترميز | **24 fps** |

> **ملاحظة أداء حاسمة:** الإضافة تفصل بوضوح بين "الحمولة الخفيفة الدائمة" (546 KB) و"الحمولة الثقيلة عند الطلب" (809 KB + 3.5 MB). لا يُحمّل محرك 3D إطلاقًا حتى يضغط المستخدم زر التفعيل. هذا هو النمط الذي يجب اتباعه.
